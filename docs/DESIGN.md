# 청춘다이스 소프트웨어 설계 문서

Oct 3, 2026 · @삼성꿈\_3기

## 1. 개요

청춘다이스는 브라우저에서 혼자 플레이하는 고교생활 보드게임이다. 주사위로 16칸 학교 판을 세 바퀴(3년) 돌며 선택을 하고, 쌓인 능력치·진로 레벨·운으로 졸업 후 직업이 정해진다.

게임 판정은 모두 정해진 규칙(주사위 + 보정)으로 클라이언트에서 계산한다. 사건·선택지 글은 개발 단계에서 LLM으로 미리 작성해 JSON으로 저장하고, 게임 실행 중에는 AI를 호출하지 않는다.

| 구분 | 내용 |
| --- | --- |
| 플랫폼 | 웹 게임 (PC·태블릿 가로 우선, 모바일 세로 지원) |
| 플레이 | 1인, 한 판 약 32턴, 15\~20분 |
| 포함 | 성향 선택, 입학 주사위, 보드 이동, 칸별 사건·선택·판정, 버프, 상점, 동아리, 진로 레벨, 엔딩 연출, 결과 공유, 엔딩 도감, 익명 플레이 통계 |
| 제외 (이후 확장) | 멀티플레이, 로그인·계정, 실행 중 AI 생성, 서버 측 판정, 결제 |
| 저장소 / 배포 | GitHub → Vercel (Hobby 플랜) |
| 데이터베이스 | Supabase 무료 플랜 (익명 통계 전용, 없어도 게임은 동작) |

## 2. 시스템 아키텍처

게임은 브라우저 안에서 완결되고, 서버는 정적 파일 제공과 익명 통계 저장만 맡는다. 인터넷이나 Supabase가 끊겨도 이미 열린 게임은 끝까지 플레이된다.

**원칙**

1. **엔진과 화면 분리** — 게임 규칙은 React를 모르는 순수 TypeScript 함수로 만든다. 같은 엔진을 화면, 단위 테스트, 밸런스 시뮬레이션이 함께 쓴다.
2. **규칙은 코드, 내용은 데이터** — 사건 문장·선택지·수치·직업표는 JSON 파일로 두고, 빌드 때 스키마 검사를 통과해야 배포된다.
3. **같은 시드, 같은 결과** — 모든 난수는 시드 기반 생성기에서 나온다. 버그 재현과 시뮬레이션이 쉬워진다.
4. **외부 서비스는 선택** — Supabase 전송은 실패해도 게임에 영향을 주지 않는다. 키가 없으면 통계 기능만 꺼진다.

**추천 기술 스택**

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Next.js (App Router) + TypeScript | Vercel과 설정 없이 연동, 결과 공유 페이지의 미리보기 이미지(OG) 생성 가능 |
| 상태 관리 | Zustand + persist | 게임 상태 하나를 가볍게 보관, 새로고침해도 이어하기 |
| 스타일 | Tailwind CSS | 화면 수가 적고 빠르게 만들기 좋음 |
| 애니메이션 | Framer Motion | 주사위 굴림, 말 이동, 룰렛, 엔딩 연출 |
| 데이터 검증 | Zod | 콘텐츠 JSON과 저장 데이터 검사를 한 스키마로 |
| 테스트 | Vitest (+ 선택: Playwright) | 엔진 단위 테스트와 시뮬레이션 스크립트 실행 |
| 패키지 관리 | pnpm | 빠른 설치, Vercel 기본 지원 |
| DB | Supabase (Postgres) 무료 플랜 | 익명 플레이 기록과 엔딩 통계 |
| 배포 | Vercel Hobby + GitHub 연동 | 푸시하면 자동 배포, PR마다 미리보기 주소 |

게임 화면은 캔버스 엔진(Phaser 등) 대신 HTML·CSS 격자로 그린다. 5×5 보드와 텍스트 선택지 위주라 캔버스가 필요 없고, 글자 크기·접근성·반응형 처리가 쉬워진다.

## 3. 프로젝트 구조

저장소는 하나(모노레포 아님)로 두고, `src/engine`은 React·브라우저 API를 import하지 않는다는 규칙만 지킨다.

│  ├─ events/                # 장소·돌발·일반 칸 사건

│  ├─ clubs.json  routes.json  buffs.json  items.json

## 4. 게임 엔진

엔진은 `reduce(state, action) → { state, log }` 함수 하나로 움직인다. 화면은 `state.phase`를 보고 무엇을 그릴지 정하고, 플레이어 입력은 모두 액션으로 보낸다.

**상태 데이터**

```ts
type Stat = 'study' | 'stamina' | 'social' | 'luck';          // 학업·체력·인맥·운
type Career = 'academic' | 'sports' | 'arts' | 'comm' | 'biz'; // 학문·운동·예술·소통·경영

type Phase =
  | 'trait_select' | 'enroll_roll' | 'await_roll' | 'moving'
  | 'tile_event' | 'choice' | 'judge' | 'result'
  | 'shop' | 'route_select' | 'burnout' | 'graduation' | 'ending';

interface GameState {
  version: 1;
  seed: number; rngState: number;      // 시드 난수 상태
  phase: Phase;
  traitId: string;
  year: 1 | 2 | 3;
  position: number;                    // 0~15
  turn: number;
  stats: Record<Stat, number>;         // 0~100
  stress: number;                      // 0~100
  money: number;                       // 원
  careerExp: Record<Career, number>;   // 레벨은 경험치에서 계산
  clubId: string | null;
  routeId: string | null;              // 2학년 루트
  buffs: ActiveBuff[];                 // 최대 3개 (디버프 별도)
  debuffs: ActiveBuff[];
  records: { examPass: number; award: number; praise: number; late: number };
  flags: string[];                     // 'casting', 'viral', 'contest' 등 기적 엔딩 조건
  abilityUses: number;                 // 성향 특수 능력, 1년 2회
  seenEvents: string[];                // 같은 해 반복 방지
  pending?: PendingEvent;              // 지금 보여 줄 사건·선택지·판정 결과
  finalExamBonus: boolean;             // 3학년 진로 시험 성공
  ending?: EndingResult;
  startedAt: number;
}

type Action =
  | { type: 'SELECT_TRAIT'; traitId: string }
  | { type: 'ROLL_ENROLL' } | { type: 'ENROLL_PICK_STAT'; stat: Stat }
  | { type: 'ROLL_MOVE' } | { type: 'STEP_DONE' }
  | { type: 'CHOOSE'; optionId: string }
  | { type: 'USE_ABILITY' } | { type: 'CONTINUE' }
  | { type: 'BUY'; itemId: string } | { type: 'LEAVE_SHOP' }
  | { type: 'SELECT_ROUTE'; routeId: string }
  | { type: 'ROULETTE_REROLL'; accept: boolean };
```

**난수**

- `mulberry32(seed)`를 쓰고, 다음 난수 상태를 `rngState`에 저장한다. 저장 후 다시 열어도 같은 결과가 나오므로 새로고침으로 주사위를 다시 굴리는 것도 막힌다.
- 주사위 값은 엔진이 먼저 정하고, 화면은 그 값으로 멈추는 애니메이션만 보여 준다.

**이동 처리**

1. `ROLL_MOVE` → 이동 주사위 `[1,1,1,2,2,3]` 중 하나.
2. 한 칸씩 전진하며, 코너(0·4·8·12)에 닿으면 남은 눈과 관계없이 멈춘다.
3. 칸 0(진급)에 멈추면 `year`가 1 오른다. 3학년을 마치고 칸 0에 오면 `graduation`.
4. 칸을 지날 때마다 "N칸 이동" 버프 수명을 줄인다.
5. 멈춘 칸의 처리기(`tiles/`)가 `pending`을 만들고 `phase`를 정한다.

**판정 처리** (`rules.ts`)

```ts
judge({ base, diff, bonuses, state }) {
  const d1 = roll6(), d2 = roll6();
  const total = d1 + d2 + statBonus(base) + sum(bonuses) + stressMod(state);
  if (d1 + d2 === 12) return 'critical';
  if (d1 + d2 === 2)  return 'fumble';   // 운빨형 능력으로 'fail'로 바꿀 수 있음
  return total >= diff ? 'success' : 'fail';
}
```

## 5. 게임 규칙 명세

아래 숫자는 모두 `content/`의 JSON 또는 `rules.ts`의 상수로 두어, 코드 수정 없이 조정할 수 있게 한다.

### 5.1 수치 체계

| 종류 | 항목 | 범위 | 쓰임 |
| --- | --- | --- | --- |
| 기본 능력치 | 학업, 체력, 인맥, 운 | 0\~100 | 판정 보정, 선택지 조건, 엔딩 등급 |
| 게이지 | 스트레스 | 0\~100 | 단계별 효과 |
| 화폐 | 돈 | 0 이상 | 상점, 선택지 비용, 경영 엔딩 |
| 진로 레벨 | 학문, 운동, 예술, 소통, 경영 | Lv0\~5 | 진로 판정 보정, 선택지 해금, 엔딩 분야 |

**성장 제한**

- 기본 능력치·스트레스는 0\~100으로 자른다.
- 기본 능력치가 80을 넘은 상태에서 오르는 양은 절반(내림, 최소 1).
- 사건 하나가 바꾸는 양은 항목당 최대 ±20. 콘텐츠 검사에서 막는다.
- 진로 레벨은 Lv5가 최대(경험치는 계속 쌓일 수 있음).

### 5.2 판정

주사위 2개 합 + 보정 ≥ 난이도이면 성공. 난이도는 쉬움 6 / 보통 8 / 어려움 10. 눈 합 12는 대성공, 2는 대실패(보정과 무관).

| 기본 능력치 | 0\~19 | 20\~39 | 40\~59 | 60\~79 | 80\~100 |
| --- | --- | --- | --- | --- | --- |
| 보정 | −1 | 0 | +1 | +2 | +3 |

| 진로 레벨 | Lv0 | Lv1\~2 | Lv3\~4 | Lv5 |
| --- | --- | --- | --- | --- |
| 보정 | 0 | +1 | +2 | +3 |

- 사건마다 판정 기준을 하나 지정한다: 기본 능력치 4개 중 하나 또는 진로 레벨 5개 중 하나.
- 운은 주사위를 바꾸지 않고, 돌발 칸 판정과 졸업 판정에서 결과에 보정으로만 더해진다.

### 5.3 스트레스 단계

| 스트레스 | 상태 | 효과 |
| --- | --- | --- |
| 0\~29 | 여유 | 모험형 선택지 판정 +1 |
| 30\~59 | 보통 | 없음 |
| 60\~79 | 지침 | 모든 판정 −1 |
| 80\~99 | 위험 | 성장형 선택지 잠김, 휴식형 스트레스 감소 2배 |
| 100 | 번아웃 | 즉시 `burnout` 단계: 다음 턴 쉬고, 체력 −10, 스트레스 50으로 |

### 5.4 성향

모든 성향은 돈 1만 원, 진로 레벨 전부 Lv0(경험치 0)에서 시작한다. 특수 능력 사용 횟수는 1년에 2번, 진급 칸에서 초기화.

| 성향 | 학업 | 체력 | 인맥 | 운 | 스트레스 | 특수 능력 | 약점 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 재능형 | 60 | 30 | 30 | 40 | 10 | 시험 판정 항상 +2 | 학업 상승량 −5 (최소 +1) |
| 노력형 | 50 | 45 | 40 | 25 | 30 | 학업 판정 실패 시 학업 +3 | 없음 (높은 시작 스트레스) |
| 운동형 | 25 | 65 | 40 | 30 | 20 | 스트레스 증가량 항상 −5 (최소 0) | 시험 난이도 +1 |
| 인싸형 | 30 | 35 | 65 | 30 | 20 | 1년 2회, 판정 기준을 인맥으로 바꿈 | `refuseFavor` 태그 선택 시 스트레스 +10 |
| 운빨형 | 35 | 35 | 30 | 60 | 10 | 1년 2회, 대실패를 일반 실패로 | 없음 |

**입학 주사위** (성향 선택 직후 출발 칸에서 1회): 1 학업 +10 / 2 체력 +10 / 3 인맥 +10 / 4 운 +10 / 5 스트레스 −10 / 6 원하는 능력치 +10

### 5.5 보드

5×5 테두리 16칸, 시계 방향. 한 바퀴 = 1년, 세 바퀴 후 칸 0 도착 = 졸업.

| 칸 | 이름 | 종류 | 칸 | 이름 | 종류 |
| --- | --- | --- | --- | --- | --- |
| 0 | 진급 (출발) | 코너 | 8 | 여름방학 | 코너 |
| 1 | 등굣길 | 장소 | 9 | 동아리방 | 장소 |
| 2 | 급식실 | 일반 | 10 | 돌발 | 일반 |
| 3 | 교실 | 장소 | 11 | 운동장 | 장소 |
| 4 | 1학기 시험 | 코너 | 12 | 2학기 시험 | 코너 |
| 5 | 돌발 | 일반 | 13 | 상담실 | 장소 |
| 6 | 도서관 | 장소 | 14 | 교무실 | 일반 |
| 7 | 보건실 | 일반 | 15 | 돌발 | 일반 |

화면 배치: 아래쪽 행 오른쪽→왼쪽이 0\~4, 왼쪽 열 아래→위가 5\~8, 위쪽 행 왼쪽→오른쪽이 9\~12, 오른쪽 열 위→아래가 13\~15. 가운데 3×3은 HUD·사건 카드 자리.

### 5.6 코너 칸

**진급 (칸 0)** — 처리 순서: 용돈 3만 원 → (1→2학년만) 2학년 루트 선택 → 겨울방학 선택 → 상점 → 특수 능력 횟수 초기화. 3학년 끝에는 졸업으로 바로 간다.

**여름방학 (칸 8)** — 용돈 2만 원 → 여름방학 선택 → 상점.

| 방학 | 선택 | 효과 | 버프 |
| --- | --- | --- | --- |
| 여름 | 알바 | 돈 +2만, 체력 −10, 경영 +4 | 성실 알바생 |
| 여름 | 학원 특강 | 돈 −2만, 학업 +10, 스트레스 +10, 학문 +4 | 선행학습 |
| 여름 | 특기 연습 (운동 또는 예술 선택) | 돈 −1만, 선택 분야 +4, 체력 +5 또는 스트레스 −5 | 연습벌레 |
| 여름 | 실컷 놀기 | 스트레스 −30, 인맥 +5 | 충전 완료 |
| 겨울 | 단기 알바 | 돈 +2만, 체력 −10, 경영 +4 | 성실 알바생 |
| 겨울 | 선행학습 | 돈 −2만, 학업 +10, 스트레스 +10, 학문 +4 | 선행학습 |
| 겨울 | 가족 여행 | 인맥 +5, 운 +5, 스트레스 −15, 소통 +4 | 여행의 추억 |
| 겨울 | 특기 연습 (운동 또는 예술 선택) | 돈 −1만, 선택 분야 +4 | 연습벌레 |

돈이 모자라는 선택지는 비활성화하고 "용돈 부족"을 표시한다.

**시험 (칸 4·12)** — 전략을 고른 뒤 학업 판정(보통 8).

| 전략 | 판정 | 부가 효과 |
| --- | --- | --- |
| 밤샘 벡락치기 | +2 | 스트레스 +15, 디버프 밤샘 후유증 |
| 평소 실력대로 | 0 | 없음 |
| 컨디션 관리 | −1 | 체력 +5, 스트레스 −10 |

성공: 학업 +10, 시험 기록 +1. 대성공: 학업 +15, 시험 기록 +1, 버프 선생님의 신뢰. 실패: 스트레스 +10. 시험은 진로 경험치를 주지 않는다.

3학년은 칸 4가 모의고사(위와 같은 규칙), 칸 12가 **진로 시험**이다. 경험치가 가장 높은 진로로 종류가 정해진다(학문 수능, 운동 실기, 예술 오디션, 소통 면접, 경영 창업 발표). 그 진로 레벨로 보통(8) 판정, 전략 선택은 같다. 성공하면 그 진로 +5와 `finalExamBonus`(졸업 판정 +1), 실패하면 스트레스 +10.

## 6. 엔딩 계산

진로 레벨이 어떤 직업이 될지의 후보와 확률을 정하고, 운이 그중 하나를 고르며, 기본 능력치가 직업 등급에 영향을 준다. `ending.ts`는 아래 순서를 그대로 따른다.

1. **친구 구원 확인** — 인맥 70 이상이고 소통을 뚜 모든 진로가 Lv1 이하이면 친구 구원 엔딩. 구원하는 친구는 무작위. 등급 판정 없음.
2. **기적 엔딩 확인** — 기적 플래그(`casting`, `viral`, `contest`)가 하나 이상 있으면 운 ÷ 10 % 확률로 발동(운 60이면 6%). 여러 개면 무작위로 하나. 등급 판정 없음.
3. **룰렛 후보 만들기**
   - 진로 Lv2 이상인 분야 → 가중치 Lv²
   - 두 분야가 모두 Lv3 이상 → 조합 직업, 가중치 (두 Lv 평균)²
   - 졸업 때 돈 15만 원 이상 → 경영이 Lv2 미만이어도 Lv2 가중치로 후보 추가
   - 후보가 없으면 "아직 나를 찾는 중" 엔딩으로 끝
4. **룰렛 돌리기** — 가중치 비례 추첨. 운 60 이상이면 결과를 본 뒤 1회 다시 돌릴지 고를 수 있고, 다시 돌리면 두 번째 결과로 확정.
5. **졸업 판정** — 주사위 2개 + 아래 보정의 합으로 등급을 정한다. 조합 직업은 두 분야 중 높은 쪽 기준.

| 보정 | 값 |
| --- | --- |
| 진로 레벨 | 진로 레벨 보정표 (0\~+3) |
| 관련 기본 능력치 | 학문=학업, 운동=체력, 소통=인맥, 예술=학업·체력·인맥 중 최고값 (−1\~+3) |
| 경영의 돈 | 경영 분야는 능력치 대신 남은 돈: 10만 +1 / 20만 +2 / 30만 +3 |
| 운 | 기본 능력치 보정표 (−1\~+3) |
| 3학년 진로 시험 성공 | +1 |
| 스트레스 80 이상 | −1 |

| 합계 | 등급 |
| --- | --- |
| 13 이상 | 상위 |
| 9\~12 | 중위 |
| 8 이하 | 하위 |

예를 들어 운동 Lv4·체력 60·운 30·진로 시험 성공(보정 +5)이면 상위 약 42%, 하위 약 8%다. 운동 Lv2·체력 40·운 30(보정 +2)이면 상위 약 8%, 하위 약 42%다. 기준값은 `rules.ts` 상수로 두고 테스트 플레이 후 조정한다.

6. **에필로그** — 스트레스 80 이상이면 "번아웃 주의" 문구, 돈이 많이 남으면 "모아 둔 돈으로 …" 문구를 결과 화면에 덧붙인다. 결과 화면에는 룰렛에 있던 모든 후보와 확률("될 수 있었던 직업들")을 함께 보여 준다.

| 소통 + 예술 | 인기 크리에이터 | 방송 PD | 영상 편집자 |
| 운동 + 소통 | 스포츠 캐스터 | 스포츠 에이전트 | 체육 행사 진행자 |
| 소통 + 경영 | 프랜차이즈 대표 | 영업 전문가 | 매장 매니저 |
| 학문 + 운동 | 스포츠 의학 의사 | 체육 교사 | 운동 코치 |
| 학문 + 소통 | 기자 | 홍보 담당 | 학원 상담 실장 |
| 운동 + 경영 | 스포츠 브랜드 대표 | 헬스장 사장 | 스포츠 용품 판매 |
| 예술 + 경영 | 엔터테인먼트 대표 | 갤러리 운영 | 핸드메이드 샵 |

세 분야 이상이 Lv3이면 가능한 조합이 모두 후보가 된다.

**특별 엔딩**

| 엔딩 | 조건 | 직업 |
| --- | --- | --- |
| 기적: 길거리 캐스팅 | `casting` | 길거리 캐스팅 배우 |
| 기적: 바이럴 | `viral` | 바이럴 스타 크리에이터 |
| 기적: 발명 | `contest` | 발명 특허 창업가 |
| 친구 구원 | 1단계 조건 | 무작위 친구: 창업동아리 친구 → 공동창업자 / 밴드부 친구 → 가수 매니저 / 방송부 친구 → 채널 PD / 운동부 친구 → 구단 직원 / 코딩반 친구 → 기업 홍보 담당 / 소꿉친구 → 카페 공동 운영 |
| 탐색 | 후보 없음 | 아직 나를 찾는 중 (갭이어, 세계 여행) |

**친구 구원 연출**: 룰렛이 "아직 나를 찾는 중"에 멈추고 실패 문장이 이어지며 화면이 어두워진다 → "졸업식 날 밤, 휴대폰이 울렸다" → 친구의 제안 → 직업 확정과 "친구 구원 엔딩" 표시. 연출 단계는 `EndingResult.sequence` 배열로 엔진이 만들고 화면은 순서대로 재생만 한다.

```ts
interface EndingResult {
  kind: 'normal' | 'combo' | 'miracle' | 'rescue' | 'explore';
  jobId: string;
  grade?: 'top' | 'mid' | 'low';
  candidates: { id: string; weight: number; probability: number }[];
  rerolled: boolean;
  graduationRoll?: { dice: [number, number]; bonus: number; total: number };
  epilogue: string[];
  sequence: ('roulette' | 'fail_scene' | 'phone_call' | 'grade_roll' | 'reveal')[];
}
```

## 7. 콘텐츠 데이터

사건은 LLM으로 초안을 만들고, 검사 스크립트와 사람의 검수를 거쳐 `content/events/*.json`에 커밋한다. 엔진은 효과를 정해진 키로만 읽으므로, 사건을 늘려도 코드는 바뀜지 않는다.

**사건 형식**

```json
{
  "id": "classroom_y1_group_project",
  "tile": "classroom",
  "years": [1, 2],
  "requires": { "routeId": null, "clubId": null, "minStats": {} },
  "title": "잠수 탄 조원",
  "text": "조별 과제 발표 날, 조원 한 명이 연락을 끊었다.",
  "options": [
    {
      "id": "solo", "kind": "growth", "label": "혼자 다 준비한다",
      "effects": { "stats": { "study": 10 }, "stress": 15, "career": { "academic": 3 } }
    },
    {
      "id": "persuade", "kind": "adventure", "label": "조원을 찾아가 설득한다",
      "check": { "by": "social", "diff": 8 },
      "onSuccess": { "stats": { "social": 10 }, "career": { "comm": 5 }, "records": { "praise": 1 } },
      "onFail":    { "stress": 10, "career": { "comm": 1 } },
      "resultText": { "success": "조원이 사과하며 자료를 내밀었다.", "fail": "끝내 답이 없었다." }
    },
    {
      "id": "skip", "kind": "rest", "label": "대충 얼버무린다", "tags": ["refuseFavor"],
      "effects": { "stress": -10 }
    }
  ]
}
```

- `effects`의 키는 `stats`, `stress`, `money`, `career`, `records`, `buff`, `debuff`, `flag`만 허용.
- `check.by`는 기본 능력치 4개 또는 진로 5개, 또는 `club`(내 동아리 분야).
- 해금 선택지는 `"unlock": { "career": "arts", "level": 2 }` 또는 `{ "buff": "teacher_trust" }`.
- 일반 칸(급식실·보건실·돌발)은 `options` 대신 `outcome` 하나나 `check` + `onSuccess`/`onFail`만 가진다.

**검사 규칙** (`scripts/validate-content.ts`, Zod)

| 규칙 | 이유 |
| --- | --- |
| 장소 사건은 growth·rest·adventure 각 1개씩, 해금 선택지는 최대 1개 | 선택지 틀 고정 |
| 기본 능력치·스트레스 변화 절댓값 ≤ 20, 돈 변화 ≤ 3만 | 성장 제한 |
| growth는 career +3, adventure는 성공 +5·실패 +1, rest는 career 없음 | 시뮬레이션 가정과 일치 |
| 장소별 career 분야는 5.7의 표 안에서만 | 분야 간 균형 |
| growth는 반드시 stress > 0 | "무리하기" 성격 유지 |
| 장소 × 학년마다 사건 2개 이상 | 같은 해 반복 방지 |
| 등굣길·교실에 `refuseFavor` 선택지 있는 사건 총 3개 이상 | 인싸형 약점 작동 |
| id 중복 없음, 참조하는 버프·동아리·플래그 id 존재 | 런타임 오류 방지 |
| 문장 길이: text ≤ 80자, label ≤ 20자, resultText ≤ 60자 | 부스 진행 속도, 모바일 표시 |
| 금지어 목록(폭력·비하·선정 표현) 미포함 | 청소년 대상 |

**LLM 제작 흐름**

1. `scripts/prompts/event.md`에 프롬프트 템플릿을 둔다: 장소의 한 줄 정체성, 학년 분위기, 허용 분야, 위 검사 규칙, JSON 형식 예시 1개.
2. 장소 × 학년 단위로 초안을 받아 `content/drafts/`에 저장한다.
3. `pnpm validate:content`로 검사하고, 실패 메시지를 그대로 LLM에 돌려 고친다.
4. 사람이 읽고 말투·사실관계를 고친 뒤 `content/events/`로 옮겨 PR을 연다.
5. CI가 검사와 시뮬레이션을 돌리고, 통과해야 병합한다.

**최소 분량**: 장소 5곳(상담실 제외) × 학년 3 × 2개 = 30개, 동아리 사건 9개 동아리 × 2개 = 18개, 돌발 7개, 급식실 4개.

## 8. 화면 설계

페이지는 5개다. 게임 진행은 `/play` 한 페이지 안에서 `phase`에 따라 화면이 바뀐다.

| 경로 | 화면 | 렌더링 |
| --- | --- | --- |
| `/` | 타이틀: 새 게임, 이어하기(저장본 있을 때), 엔딩 도감, 빠른 진행 설정 | 정적 |
| `/play` | 성향 선택 → 입학 주사위 → 보드 플레이 → 엔딩 연출 | 클라이언트 전용 |
| `/result` | 결과 카드 (공유용). 결과는 주소의 쿼리에 담음 | 서버 + OG 이미지 |
| `/collection` | 엔딩 도감: 본 직업, 숨겨진 엔딩 실루엣 | 클라이언트 (localStorage) |
| `/stats` | 부스용 통계: 오늘 플레이 수, 인기 성향, 직업 분포 | 서버 (Supabase 집계) |

**게임 화면 (가로, PC·태블릿)**

```
┌────────── 5×5 보드 ──────────┐ ┌── 상태 패널 ──┐
│ [8][9][10][11][12]               │ │ 2학년 · 14턴    │
│ [7]  ┌─ 사건 카드 ───┐ [13]   │ │ 학업 ████░ 62  │
│ [6]  │ 제목·상황 문장  │ [14]   │ │ 체력 ██░░░ 35  │
│ [5]  │ 선택지 버튼 ×3   │ [15]   │ │ 인맥 · 운 …     │
│      └─ 주사위 버튼 ─┘        │ │ 스트레스 게이지 │
│ [4][3][2][1][0]                  │ │ 돈 32,000원    │
└─────────────────────────────────┘ │ 진로 ★★☆☆☆ ×5  │
                                      │ 버프 카드 ×3    │
                                      └──────────────┘
```

세로(모바일)에서는 보드를 위에, 상태 요약 한 줄을 그 아래에 두고, 사건 카드는 화면 아래에서 올라오는 시트로 띄운다. 상태 전체는 탭하면 펼쳐진다.

**주요 컴포넌트**

| 컴포넌트 | 하는 일 |
| --- | --- |
| `Board` / `Tile` / `Pawn` | 16칸과 말. 이동은 칸 단위 애니메이션, 끝나면 `STEP_DONE` |
| `Dice` | 엔진이 정한 눈으로 멈추는 굴림. 이동 주사위는 1·1·1·2·2·3 면을 그린 별도 디자인 |
| `EventCard` | 상황 문장, 선택지(유형 아이콘, 예상 변화, 판정 기준과 성공 확률), 잠긴 선택지의 이유 |
| `JudgeOverlay` | 판정 주사위 2개 + 보정 내역 + 결과 |
| `StatPanel` | 능력치 막대, 스트레스 단계 색, 돈, 진로 별과 경험치 막대, 버프 |
| `Toast` | "예술 Lv2 달성!", "버프 획득" 같은 변화 알림 |
| `Shop` / `RouteSelect` / `ClubSelect` | 코너·동아리방 전용 화면 |
| `Roulette` / `EndingScene` | 엔딩 연출, `sequence` 순서대로 재생 |

**사용성**

- 선택지마다 성공 확률을 미리 보여 준다(예: "인맥 판정 · 성공 58%"). 운빨 요소가 있어도 판단은 플레이어가 하게.
- 빠른 진행 설정: 주사위·이동 애니메이션 단축, 결과 창 자동 닫힘. `prefers-reduced-motion`이면 기본 켜짐.
- 키보드: Space 주사위, 1·2·3 선택지, Enter 계속.
- 글자는 최소 16px, 색만으로 구분하지 않고 아이콘·문구를 함께 쓴다.

## 9. 저장과 Supabase

진행 중인 게임과 엔딩 도감은 브라우저에, 끝난 판의 익명 요약만 Supabase에 저장한다. 로그인은 없고 이름·연락처 등 개인정보는 수집하지 않는다(플레이어 대부분이 청소년).

**브라우저 저장 (localStorage)**

| 키 | 내용 |
| --- | --- |
| `yd:save` | 진행 중인 `GameState` (매 액션 후 저장). `version`이 다르면 버리고 새 게임 |
| `yd:collection` | 본 엔딩 id 목록과 처음 본 날짜 |
| `yd:settings` | 빠른 진행, 소리 |
| `yd:sent` | 통계 전송에 실패한 결과 (다음 접속 때 재전송, 최대 20개) |

localStorage를 쓸 수 없는 환경(시크릿 창 등)에서는 메모리에만 두고 게임은 그대로 진행한다. 모든 읽기·쓰기는 try/catch로 감싼다.

**Supabase 테이블** (`supabase/migrations/0001_init.sql`)

```sql
create table public.play_results (
  id            uuid primary key,              -- 클라이언트가 만든 값 (중복 전송 방지)
  created_at    timestamptz not null default now(),
  client_version text not null,
  trait_id      text not null,
  ending_kind   text not null check (ending_kind in ('normal','combo','miracle','rescue','explore')),
  job_id        text not null,
  grade         text check (grade in ('top','mid','low')),
  career_levels jsonb not null,                -- {"academic":3,...}
  final_stats   jsonb not null,                -- 학업·체력·인맥·운·스트레스·돈
  club_id       text,
  route_id      text,
  turns         int  not null check (turns between 1 and 200),
  duration_sec  int  not null check (duration_sec between 0 and 7200),
  booth_mode    boolean not null default false
);

alter table public.play_results enable row level security;

-- 익명 사용자는 넣기만 가능, 읽기·수정·삭제 불가
create policy "anon insert" on public.play_results
  for insert to anon with check (true);

-- 집계만 반환하는 함수 (개별 행은 노출하지 않음)
create function public.get_stats(since timestamptz default now() - interval '1 day')
returns json language sql security definer set search_path = public as $$
  select json_build_object(
    'plays',  (select count(*) from play_results where created_at >= since),
    'traits', (select json_object_agg(trait_id, n) from (select trait_id, count(*) n from play_results where created_at >= since group by 1) t),
    'jobs',   (select json_object_agg(job_id, n)   from (select job_id,   count(*) n from play_results where created_at >= since group by 1) j)
  );
$$;
grant execute on function public.get_stats to anon;
```

- 클라이언트는 엔딩이 확정되는 순간 `insert`를 한 번 보내고, 실패하면 `yd:sent`에 넣는다. 게임 흐름은 기다리지 않는다.
- 브라우저에는 공개(anon) 키만 쓴다. service role 키는 쓰지 않는다.
- `/stats`는 서버에서 `get_stats()`를 호출해 30초 캐시한다.
- 데이터 양: 한 판 약 1KB, 1만 판이어도 약 10MB로 무료 플랜 DB 500MB에 크게 못 미친다.

**결과 공유**

공유 링크는 DB를 쓰지 않고 주소에 결과를 담는다: `/result?d=<base64url(JSON)>`. 담는 내용은 성향, 직업 id, 등급, 진로 레벨, 능력치, 버전. `/result`는 Zod로 검사하고 잘못된 값이면 타이틀로 보낸다. 미리보기 이미지는 `next/og`로 만든다. 부스에서는 결과 화면에 이 주소의 QR 코드를 띄워 휴대폰으로 가져가게 한다.

주소를 손으로 고치면 가짜 결과를 만들 수 있지만, 랭킹이나 보상이 없으므로 막지 않는다.
